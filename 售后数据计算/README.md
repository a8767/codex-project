# 售后数据计算

## 使用入口

项目根目录：`C:\Users\lu\Desktop\售后数据计算`。主程序按原始记录计算，不用答案表回填数字。业务规则见[算法规范](算法规范.md)，当前实现、验证范围与待办见[项目状态](项目状态.md)。

```powershell
cd 'C:\Users\lu\Desktop\售后数据计算'
python generate_monthly_reports.py --month 2026-09 --created-date 20260924 --raw-dir '.\原始数据20260923'
```

主程序需要 Python 3.10+、`openpyxl`。命令是运行示例，本次模板适配没有执行重算。运行会写入统计表、登记错误清单，并尝试标红原始记录；请先关闭相关 Excel/WPS 文件。同名普通报表会被覆盖，个人表的人工复核保留规则见算法规范第12节。

影刀调用项目内 `影刀_售后月度数据计算.py` 的 `generate_report(month, created_date, root, overwrite)`。该入口不提供 `raw_dir` 参数。文件已更新不等于影刀应用内粘贴的模块已经同步，使用前需核对实际模块。

## 目录和日期

| 位置 / 参数 | 作用 |
|---|---|
| 原始数据或带“原始”关键字的目录 | 输入；未传 `--raw-dir` 时先找固定目录，否则按候选目录名称倒序取首个，并非按修改时间挑选 |
| 数据表模板 | 8份输出模板，以及个人表使用的售后分组、考核设置 |
| 数据计算 | 输出统计表与 `数据登记错误.xlsx`；不作为计算输入 |
| `--month` | 售后事件月份筛选；销售数据取本批源表数值，须人工确保覆盖同一期间 |
| `--created-date` | 文件名后缀，不是业务日期，也不会将月度汇总转换成日度数据 |

源文件优先使用旧固定文件名，否则按表名关键词选择 `.xlsx` 文件，忽略 `~$` 锁文件；选定后检查所需字段。当前并非按内容自动遍历重选最佳文件，同类多份文件也没有“最新日期优先”保证，建议每批每类只保留一份有效源表。

原7表当前日期标签取统计月份内可识别的补发登记时间最大日期，无可识别日期则退回月份；统计筛选仍是整月。该实现与月度标签规范有待统一，详见算法规范第10节。

## 输出与个人绩效

常规计算入口生成总数据计算、小组统计表、大组统计表、工厂统计表、车型统计表、配件统计表、店铺统计表、售后个人数据统计表，共8份统计表，文件名追加创建日期；另生成登记错误清单。

个人表使用新版三页模板：`个人绩效汇总`、`考核异常明细`、`考核设置`。写入器从摘要和明细页读取表头，并按模板第二行样式填数据；缺少必要表头时会报明确信息。当前摘要字段已适配新模板的21列，“数据登记日期”沿用本批补发登记时间最大日期。重新生成同名文件会读取新模板，因此仍按记录ID保留人工复核，摘要备注按月份＋姓名衔接。旧单页小组式模板不能直接替代。人员优先读 `数据表模板/售后分组.xlsx`，不存在时回退原始目录；组织报表仍从原始目录读取售后分组，不可认为模板名单已自动供所有报表共用。

个人退货优先按“实际同意退货售后”，补偿优先按“实际同意补偿售后”归集；为空时取“操作售后”，并在备注中说明原因及条数。个人补发直接按“操作售后”归集；归属字段为空或缺失时保留未归属提示，不回退原表“登记人”。不分摊销售额、销售订单量或万里牛。配件店补发包含在个人补发登记次数中并另列其中项。名单外人员保留提示，昵称仅按已确认设置映射。完整算法、去重和复核保存规则集中在[算法规范第12节](算法规范.md#12-售后个人绩效统计)。

## 核验与缺失处理

- 总表补发次数＝本表有效订单补发＋万里牛数量；小组、大组主补发扣除配件店补发并另列，不能直接强求各表总数相等。
- 工厂、车型、配件、店铺各指标有独立筛选及映射条件。配件以日销“单选”归并；工厂名单来自工厂数据，河北仓库/永康云仓订单量为0。具体名单只在算法规范维护。
- 原始表缺失保留其余可计算数据并说明缺失；万里牛只汇总与本月补发登记表“登记时间”逐日匹配的记录，缺失或没有同日记录填0。缺模板、输出被占用等并不在源数据容错保证内。
- 店铺名为空标记登记错误，但仍可参与不依赖店铺的合规指标。错误清单不是“全部不参与计算”的清单；先计算导出，再尝试标红，影刀返回 `marking_failures` 提示未标红文件。
- 同一运行缓存读取结果。金额汇总原始精度后保留两位小数；核对必须使用相同期间、筛选和归属，不以答案整数展示反改原始金额。
