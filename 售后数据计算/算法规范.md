# 售后数据计算算法规范（逐表独立口径）

修订日期：2026-09-24（文档核对，不改变计算代码或重算历史报表）。适用程序：`generate_monthly_reports.py`、`影刀_售后月度数据计算.py`。实现与输出状态见[项目状态](项目状态.md)。

## 1. 规则边界与读取约定

### 1.1 逐表配置原则

原七张业务表分别定义数据来源、期间、输出范围、过滤条件、归属、计量和比率；新增第八张个人绩效表见第12节。某表的店铺排除、模板名单、工厂必填、组织必填、配件扣除等规则，不自动传播到其他表或其他指标。同一张表的退货、补发和补偿也不得默认共用过滤集合。

本文件是分表计算口径的主规范。`补发数据采集与统计规则明细.md` 中“所有补发先执行统一规则”等表述不再具有跨表约束力；与本文件冲突的内容见第 10 节。在线配置和现有代码用于核查实现，不因代码当前如此就自动成为业务规则。未明确的冲突不得静默选取、据此改代码或重算。

2026-09-24静态核对：两份程序均已包含工厂退货独立筛选、万里牛汇总及个人绩效逻辑；不再笼统标为“尚未实现”。这不表示所有规范矛盾已解决，也不代表影刀应用内模块和当前输出已通过重跑验收。2026-09-20的18点答案与用户补充截图只校准已覆盖场景，其他未决项见第10节。

### 1.2a 新增记录及备注（2026-09-22用户确认）

新增原始记录按所属表的算法正常计算，不能仅因答案表或旧模板没有该名称而删除已计算的输出行。仍保留各指标明确的业务条件，例如工厂名单、配件单选标准和补发模板准入；这不授权绕过这些条件。

默认以对应模板非空首列名单判断“新增记录（相对模板名单）”，不把模板外误称为答案外。备注追加新增说明、原始文件名和行号，多行来源列前5处并注明总行数，保留原有缺失/异常备注。由编码或组织映射生成且无法直接定位的名称注明需核实对应关系，不猜源行号。模板为空时不把所有数据标记为新增。

店铺导出阶段不再删除按算法已算出的模板外店铺；其补发是否计入仍遵循该指标的模板准入规则，并在备注说明。配件日销单选中新增的有效型号按真实销售额、销量计算并加备注，不按答案删减。

### 1.2 技术与展示约定（不包含业务过滤）

- 文件允许使用业务名称或日期后缀；按目录、文件名和表头识别。可用 `--raw-dir` 指定原始数据目录。
- 原始字段与源行号必须可追溯。销售额、补偿金额汇总原始数值后保留两位小数，禁止累加逐行取整的辅助金额。数量为整数，比率保存数值并显示百分比。
- 每个比率的分子、分母在所属表中明确；分母为零时按既有约定输出 0，不表示业务无异常。
- 同一批运行可缓存原始记录，但缓存不得预先删除只被某张表排除的记录。每个“表 × 指标”独立筛选。
- 退货、订单补发按通过该表筛选的登记记录逐条计数；万里牛按数量字段求和。未制定去重键时，不因订单号重复擅自去重，也不把重复导入视为新业务事件；发现重复导入需单独标记核查。
- 源文件缺失、无工作表、表头或必要字段时，仅影响依赖该输入的表和指标。保留可计算部分并在备注列说明；一般输入缺失不等同于真实零，无可计算明细时输出缺失提示。万里牛补发为用户明确指定的例外：文件未提供或期间内没有记录时，对应万里牛补发字段填数值 0，不阻断计算，不把主指标置为空；有有效记录时按数量正常汇总。文件存在但无法读取、缺少必要字段或数量非法属于输入异常，保留异常说明，不能声称已完整汇总。
- 店铺名称为空仍按既有登记错误流程标红、导出 `数据登记错误.xlsx`，保留来源表格及源行号。该标记不自动排除工厂、车型或配件等不依赖店铺归属的指标；是否纳入由各表决定。先计算及导出清单，再标红原始表；标红失败不改变统计数。
- 本文的月份口径是按运行参数 `YYYY-MM`，售后事件读取各自登记时间，万里牛读取日期；无年份日期使用统计年份。日度核对应限定同一具体日期，不能仅把月度数据改成某天标签。月度输出日期统一为 `YYYY-MM`，月份辅助字段为 `YYYYMM`；具体日度模式的程序支持及现有日期冲突见第 10 节。

## 2. 总数据计算表 / 当日汇总

**来源和期间**：店铺规范提供销售控制数；退货、补发、补偿按各自登记时间筛选统计期间；万里牛仅纳入与统计月份内补发登记表“登记时间”日期逐日匹配的数量。店铺规范销售数必须覆盖相同期间，不重复累计同一销售快照。

**输出粒度**：每个统计期间一行。店铺归属依赖标准店铺名称；缺失或未匹配的记录不进入依赖店铺的总表指标，保留差异清单。

| 指标 | 本表筛选、归属及计算 |
|---|---|
| 营业额、订单量 | 店铺规范中名称非空且不在 S2 的店铺，分别汇总当日真实营业额、车子销量；不要求售后组有值 |
| 退货单量 | 工厂有值；执行 R6 和 R原因；店铺完全匹配标准名称；每条计 1 |
| 签收退货单量（如有） | 仅对本表有效退货应用签收判定 |
| 订单补发 | 执行 B有效、B3、S2；仅保留店铺模板名单内且可完全匹配的门店；组织补发归属非空；每条计 1，包含只销配件店补发。本项按现有代码和2026-09-20答案明确，不从总表订单补发扣配件店数量 |
| 万里牛补发 | 日期属于统计月份且与补发登记表“登记时间”有相同日记录、售后组非空的数量合计；按数量而非记录条数统计；缺失或无同日记录填 0 |
| 补发次数 | 本表订单补发 + 本表万里牛补发 |
| 补偿金额 | 工厂有值，是否不参与计算判断为“否”；执行 C4、S2；店铺完全匹配后汇总原始补偿金额 |
| 退货率、补偿率、补发率 | 退货单量÷订单量；补偿金额÷营业额；补发次数÷订单量 |
| 日期 | 月度 YYYY-MM；日度仅在明确日度筛选时显示 YYYY-MM-DD |
| 已确认登记表无误 | 现有模板固定“已确认”，仅为模板值，不构成数据完整或人工复核通过的证据；缺失提示仍须保留 |

**核对**：用本表独立筛选的原始记录验证，不以店铺、工厂或商品表合计替代总表原始控制数。

## 3. 小组统计表

**来源和期间**：店铺规范、售后分组、退货、补发、补偿、万里牛；售后按登记时间、万里牛按日期筛选同一期间。

**输出粒度及归属**：每期间每售后小组一行。销售按店铺实际负责人匹配成员所属组，缺失时取店铺售后组；退货取退货记录售后组；补偿取记录售后组，缺失时按店铺负责人匹配成员、再取店铺售后组；订单补发使用组织补发归属；万里牛直接按登记售后组。无法归属的记录单列核查，不随意分摊。

| 指标 | 本表筛选、归属及计算 |
|---|---|
| 营业额、订单量 | 名称非空且不在 S2 的店铺，按本节销售归属汇总原始营业额、车子销量 |
| 配件店铺订单量 | 上述店铺中，只销配件店铺的配件销量；其他为 0 |
| 店铺退货、退货单量 | 工厂有值；执行 R6、R原因；店铺完全匹配且小组非空，每条计 1 |
| 签收退货单量 | 对本小组有效退货应用签收判定 |
| 订单补发 | 执行 B有效、B3，仅保留店铺模板内且完全匹配的门店，组织归属非空；扣除只销配件店补发。S2 是否额外适用于本指标存在旧文档/代码冲突，见第 10 节，不自动继承总表规则 |
| 配件补发次数 | 同一有效补发集合中只销配件店的记录数，单独列示 |
| 万里牛补发 | 按本小组汇总与补发登记表登记日期逐日匹配的数量；数据缺失或该组无记录填 0；不能因该组无销售或无订单补发而漏掉有万里牛数量的组 |
| 补发次数 | 本小组订单补发（已扣配件店）+ 本小组万里牛补发 |
| 补偿金额 | 工厂有值、参与判断为“否”，执行 C4、S2，店铺完全匹配且可归属小组，汇总原始金额 |
| 比率 | 退货率=退货÷订单量；签收退货率=签收退货÷订单量；补偿率=补偿金额÷营业额；补发率=主补发次数÷订单量；配件补发率=配件补发次数÷配件店铺订单量 |
| 售后率（如有） | （退货单量+主补发次数）÷订单量 |
| 日期、月份 | 月度 YYYY-MM、YYYYMM；日度须明确日筛选 |

**核对**：订单补发与配件补发互斥；与店铺表比较时须解释未归属小组及排除名单差异，不强制相等。

## 4. 大组统计表

**来源和期间**：使用第 3 节同期间小组已完成的各项数量及金额，不另行读取原始记录叠加；万里牛也只汇总一次。

**输出粒度**：每期间每大组一行。售后A1组、A2组归售后A组，B、C同理；福鼎售后、运营C组等其他名称保持原值。

| 指标 | 本表独立配置 |
|---|---|
| 营业额、订单量、配件店铺订单量 | 汇总所属小组对应字段，不另加门店或工厂筛选 |
| 退货单量、签收退货单量 | 汇总所属小组对应字段；不采用工厂退货集合 |
| 订单补发、配件补发、万里牛补发 | 分别汇总所属小组对应字段；无小组分配的万里牛不得随意分摊 |
| 补发次数 | 大组订单补发（已扣配件店）+ 大组万里牛补发 |
| 补偿金额 | 汇总所属小组原始精度金额，最后统一显示两位小数 |
| 比率 | 用大组汇总分子和汇总分母重新相除；对应分母为订单量、订单量、营业额、订单量、配件店铺订单量，不平均或累加小组比率 |
| 日期、月份 | 与被汇总小组同期间 |

**核对**：大组可加总金额、数量必须与完整的小组集合对应合计一致；大组与总表是否一致取决于组织归属和各指标口径。

## 5. 工厂统计表

**来源和期间**：工厂数据提供名单及销售数；退货、补发、补偿按各自登记时间；万里牛按日期。各指标分别读取原始记录筛选。

**输出粒度**：每期间每工厂一行，严格使用工厂数据名单，保留原顺序及零值工厂；名单外事件不新增工厂行，另列未纳入清单。

| 指标 | 本表筛选、归属及计算 |
|---|---|
| 营业额、订单量 | 取工厂数据原始字段，仅字段缺失时回退对应汇总列；河北仓库、永康云仓订单量按 0，营业额不受影响 |
| 退货单量 | 工厂有值，执行 R原因，按原始“工厂”归集，每条计 1；不执行 R6、S2 或任何店铺排除/模板名单，不要求店铺名称或售后组有值 |
| 退货原因边界 | 截回、拦截、拒收均计入退货单量；签收判定不能用于删除工厂退货 |
| 订单补发/除万里牛补发次数 | 执行 B有效；按工厂匹配优先、否则工厂归属，每条计 1；不执行 B3、S2、店铺模板名单，不要求店铺或售后组有值；不因配件店身份扣除 |
| 万里牛补发 | 按与补发登记表登记日期逐日匹配的记录及其工厂/仓库归属汇总数量，仅有明确且可映射的工厂才纳入；没有工厂/仓库字段时列为待分配，不把总量自动放入河北仓库。万里牛数据未提供或本工厂无记录时填 0；2026-09-20用户补充的8条记录均明确为河北仓库，共115次 |
| 总补发次数 | 工厂订单补发 + 工厂万里牛补发；与“除万里牛”字段分开，不重复相加 |
| 补偿金额 | 工厂有值且参与判断为“否”，按“工厂”汇总原始金额；不执行 C4、S2、店铺模板名单，不要求店铺名称或售后组有值 |
| 比率 | 退货率=退货单量÷订单量；补偿率=补偿金额÷营业额；补发率分子现有资料对是否含万里牛未统一，见第 10 节，不默认为任一口径 |
| 日期、月份 | 月度 YYYY-MM、YYYYMM；日度须明确日筛选 |

**核对**：对本表名单内的原始有效事件独立计数。工厂退货不复用总表过滤结果；因门店条件、工厂名单、零订单仓库等原因，不强制与总表合计相同。

## 6. 车型统计表

**来源和期间**：永久、菲利普、大众、玛莎拉蒂日销及编码表，退货、补发、补偿登记；销售输入需覆盖指定期间，售后按登记时间筛选。

**输出粒度及归属**：每期间每标准车型一行。售后先取可识别的车型；否则按品牌和英文/中文编码映射，兼容旧品牌专用编码。不能因工厂表取消退货门店排除而自动取消车型表对应规则。

| 指标 | 本表筛选、归属及计算 |
|---|---|
| 销售额、订单量 | 各品牌日销按车型汇总原始销售额及销量，不用已取整辅助列；不套用 S2 或店铺模板名单 |
| 退货单量 | 工厂有值，执行 R6、R原因，按品牌对应车型编码映射后逐条计数；不要求售后组有值，不额外套用店铺模板名单 |

### 11.3 在线公式、关联引用与本地边界

- 在线表中带 `fx` 标识的工厂、中文编码、英文编码整合等列是派生列；本地程序应优先使用其**已落地的结果值**，不得把网页显示文本当作公式源码重新解析。
- 车型、型号、配件型号、工厂匹配、匹配标签和只售配件店铺构成在线标准化链：原始登记 → 品牌/中英文编码 → 车型或配件归属；原始工厂 → 工厂匹配；店铺 → 平台/售后组/只售配件店铺。
- 在线“补发登记表”当前页面没有将公式源码或关联表的字段 ID 直接暴露为可读取文本；因此本规范只记录已观察到的字段链和结果口径。若线上公式变更，应重新核对字段管理页后再更新本节，不能凭字段名称推断新的计算表达式。
- 在线列表中的颜色、隐藏列、排序、分组和“计算中”状态均为界面配置或展示状态，除各表补发条款已明确的红色标签/填色排除外，不自动进入本地算法。

### 11.4 本地代码规则的优先级

1. 本地月度报表始终以第 1—10 节的字段口径、排除规则、缺失处理和分母保护为准。
2. 在线表负责提供登记事实、映射结果和核对视图；它不授权改变本地排除店铺、工厂必填、补偿参与判断或日期归属规则。
3. 当线上字段名、映射结果与本地输入文件不一致时，保留原始值、记录映射缺失，并按本地兜底分类处理；不要静默覆盖或从历史汇总表回填原始事实。
