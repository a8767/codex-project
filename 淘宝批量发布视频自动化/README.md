# 淘宝光合视频批量发布

这是一个 Windows 桌面程序。它读取 Excel 任务表，在已登录淘宝光合平台的 Chrome 中逐条上传视频、填写发布信息、关联商品并提交。第一版只处理当前登录的店铺。

## 准备

1. 安装 Python 3.11 或更新版本，并执行 `python -m pip install -r requirements.txt`。
2. 安装并连接 `bsk` 浏览器工具及其 Chrome 扩展。运行 `bsk browsers`，确认列表中有 `chrome`。如需全自动上传本地文件，在 Chrome 地址栏打开 `chrome://extensions/` → 找到 BrowserSkill 扩展 → “详情” → 打开“允许访问文件网址”。这会让扩展访问本机的 `file://` 页面，只应对信任的扩展开启。若未启用，程序会请你在任务窗口手动选择文件。
3. 在该 Chrome 中登录 [淘宝光合平台](https://creator.guanghe.taobao.com/page/) 并确认可以手动打开发布页。
4. 复制 [发布任务模板.xlsx](发布任务模板.xlsx)，在“发布任务”表第 2 行起填写任务。视频路径可以是绝对路径，也可以相对 Excel 所在文件夹。

在项目目录运行 `.\launch.ps1`，或执行 `python -m taobao_uploader`。点击“选择并导入”，检查任务预览后点击“开始”。默认勾选“仅验证填写，不提交”：程序会填写完整页面并记录“验证通过”，不会点击发布。要正式发布时取消勾选，再点击“开始”。

## 从视频文件夹生成发布草稿

点击“按文件夹生成草稿”，选择包含 MP4 的根文件夹，再选择 Excel 草稿的保存位置。程序会递归读取子文件夹，按子文件夹名称识别车型，并从 `outputs/video_reference_db/视频发布参考数据库.sqlite3` 中寻找同型号视频的类别和参考话题。例如 `GT-05/测试视频1.mp4` 会得到不带型号的标题和正文，并在“内容标签”中加入 `#GT-05`。匹配同时接受 `GT05`、`GT-05` 等常见写法，但不会把 `GT-05A` 当成 `GT-05`。

未识别明确车型的文件夹（如“氛围感视频”）不会补写车型、价格或配置。参考数据库包含 92 条通用草稿模板，以及“自行车视频文案”表里的 72 条分类文案（24 条自行车文案和 48 条原创文案库记录）。匹配先识别文件名、目录中的方向、主题与车型线索，再对照文案关键词和适用场景；文件名没有明确方向或主题时，两类方向交替并使用中性通用文案，不从榜单推断视频画面。榜单、车型、视频与话题表作为辅助证据，榜单采集批次与月榜优先采用最新数据。生成时同一批优先使用不同文案 ID 和正文，标题尽量不重复；必要时可用正文中的短句（不超过 30 字）作标题，标题仍可重复且不添加编号标记。当标题直接取自正文时，正文改为该行已确认的内容话题标签。重新生成会轮换相近主题候选。新文案不填入未经文件名、目录或商品信息确认的具体车型、价格和配置。Excel“匹配说明”包含方向、主题和文案场景；末尾的“榜单参考标题／文案／来源”是人工核对依据，不会复制进发布栏。

参考库里的 `#山地车`、`#骑行` 等关键词不是发布器可直接选择的完整活动话题名；自动填写的活动话题仍限已在平台验证的“山地骑行的快乐”和“进来一起享受骑行”。匹配到的其他榜单话题会列在“匹配说明”，供人工核对。草稿的“内容标签”列按已确认的车型类别填入相关标签，例如山地车使用“山地自行车；骑行；户外骑行”，并追加 `#GT-05` 这样的型号标签；无明确车型时只填“骑行；自行车”。程序只根据文件夹名及参考库生成草稿，**没有观看视频内容**；平台话题和内容标签也会随时间变化，因此请逐条核对标题、正文、话题、标签与画面是否相符。

草稿中的创作者声明留空，发布前必须按实际内容填写；生成的正文也要逐条核对或修改，商品 ID、封面及发布时间由你决定。草稿生成后保存并关闭 Excel，再点击“选择并导入”。生成草稿本身不会上传或发布视频。

## Excel 规则

每行一条视频。`任务编号`、`视频路径`、`标题`、`创作者声明`必填。标题最多 30 字，正文最多 1000 字。商品 ID 最多 6 个，多个用分号隔开。封面、标签、话题和发布时间可留空。`发布时间`采用北京时间 `YYYY-MM-DD HH:MM`；留空即立即发布，填写则为定时发布。平台页面提示可设置未来 2 小时至 30 天，程序在导入和填写时校验这一范围。声明须使用模板“填写说明”中的一个准确名称。

`内容标签`填写平台可搜索的词，多个用分号隔开，例如 `山地自行车;骑行;户外骑行`。程序会逐个选择搜索结果中的精确标签，并检查它们成为视频描述里的蓝色标签；填 `#骑行` 也可以。`话题`是下方“参与话题活动”的单独选项，不会替代内容标签。若某个标签已从平台下线，该行会在提交前报错，供你修改草稿。

导入会检查路径、重复编号、内容长度、商品数量及发布时间。出现错误时会指出 Excel 行号。运行状态保存在 Excel 旁边的 `.taobao_uploader/tasks.sqlite3`；每次运行都会让成功或平台判重跳过的任务重新进入网页，由平台决定是否重复。上传处理完成后若页面显示“视频可能重复发布”，该任务会登记为“跳过”，不填写后续发布内容、不点击发布；同时登记到发布统计表，备注为“视频重复上传”。本地重复任务编号不会拦截上传。内容有变化时，成功或跳过任务也可用原编号重新检查；“提交中/待核查”仍需先到后台确认结果，不能自动重发。明确失败的任务需设置 `retry_failed=True` 后重试。

后台确认作品 ID 后，程序会自动更新 `outputs/publish_stats/发布视频统计表.xlsx`。统计表包含视频作品文件名称、作品 ID、作品文案、作品话题、视频发布时间（北京时间）和备注；文案包含标题、正文及已选的 `#内容标签`，定时任务显示预约发布时间，立即发布显示提交时间。遇到平台重复提示的跳过记录会留空作品 ID 和发布时间，并在备注中写“视频重复上传”。正式作品按作品 ID 去重；验证模式和结果不明确的任务不会计入。若统计表在 Excel 中打开而无法写入，先关闭表格，再在程序中点击“更新统计表”；该按钮也会补录当前已导入任务中有作品 ID 的历史成功记录。统计记录另存于同目录的 SQLite 文件，重导出不会重复发布视频。

## 运行与恢复

- “暂停”会在提交前或当前任务结束后生效；“继续”恢复运行。需要登录或人工完成验证码时，任务窗口会保留，处理后再点“继续”。
- 提交前的页面故障最多重试两次。提交结果不明确时，任务会标为“待核查”，批次暂停。请到光合后台核对后再决定是否创建新任务；不要直接重试该行。
- “重试失败”只重置明确在提交前失败的任务。已成功任务重新运行时会再上传到平台检测，若平台没有提示重复，程序会继续发布并新增一条尝试记录。关闭窗口会请求停止，等待当前浏览器命令返回，再关闭程序。
- 测试或发布结束时，Chrome 可能询问是否离开未保存的发布页。请在任务窗口点击“离开”；程序会提示并重试关闭会话。
- 视频原文件不会移动或删除。

## 当前限制

2026-09-24 已用一条本地 MP4 在当前店铺验证：启用 Chrome 扩展的文件网址访问权限后，程序在验证模式下自动选取视频、完成上传并生成智能封面，填写标题和“内容无需标注”声明，记录为“验证通过”。随后按用户授权在浏览器里完成一次真实立即发布，标题和正文均为“测试视频”；作品管理显示 ID `2264901856221090`、公域审核通过。按用户后续要求已删除该作品，搜索“测试视频”显示 0 个结果。平台对这段视频曾提示“视频可能重复发布”。

真实提交后页面直接重置，没有停留在“发布成功”提示，因此程序到作品管理核验作品 ID。2026-09-27 已用两条本地 MP4 完成真实定时发布测试：作品 ID `2312389332965071`（GT-05）与 `4397164878252290`（通用骑行）均显示定时发布 `2026-09-28 10:00`，话题分别为“山地骑行的快乐”和“进来一起享受骑行”。首次核验曾因平台的定时记录没有立即发布的创建时间而误报“待核查”，人工确认后已修复定时记录匹配；第二条由程序自动核验成功。商品关联和品牌/内容标签仍需用实际任务验收。网站界面变化后，浏览器模块的元素定位可能需要调整。批量正式使用前请核对后台记录、封面、商品关联和发布时间。

程序不保存淘宝密码或浏览器 Cookie；它通过连接到 Chrome 的 bsk 扩展复用已有登录。浏览器命令集中在 `taobao_uploader/browser.py`，任务读取与状态恢复分别在 `tasks.py`、`state.py`。
